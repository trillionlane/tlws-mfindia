# TAG02 semantic fund tag reads

Base: `4689443d8675045d0f06bd9a3a5e213bc4eaae32` (merged TAG01). This slice adds a read-only semantic interface over TAG01's two approved consumer tables. It does not install/populate them, change source facts, infer ethical classifications or change the existing alias/news contracts.

Trusted composition uses `mfdataindia.tagging.app:create_app`, which extends the current dataset/core factory. Its deployment retains internal ingress, Google workload authentication, TI partner authorization and the direct non-elevated dedicated reader. No HTTP parameter chooses an identity or reader profile. Every request reuses the existing dataset relation/reader/dependency and lock validation once per required relation (one for fund reads, two for definitions plus their snapshot); never once per fund. No cross-request security cache is introduced.

The versioned `/api/fund-tags/v1` contract provides discovery, definition pages, exact-code detail, bounded batch reads and tag-based fund filtering. Filters match exact namespaced tag IDs, never substrings or scheme names. `match=all|any` is explicit; only supported assessments count as positive tags. Unknown/unassessed is not a negative ethical verdict. Each returned fund retains all twenty assessments, evidence hashes/dates, family-mapping state and the original version. Internal snapshot reports and original observation rows remain inaccessible.

The definition catalogue is the immutable vocabulary for the active policy version, including terms retained from earlier snapshots. A known term can have zero current matches; presence in the vocabulary is not a current positive assessment. An unknown valid tag ID likewise yields no matches. Unfiltered pages account for every code in the published census, including explicitly not-applicable out-of-scope schemes, without changing the old core API's Regular-plan defaults. Published counts describe this derived snapshot, not a fresh live-source census. Existing API pool/database timing telemetry is retained on success and failure.

Current policy reason codes determine the assessment state. Missing evidence cannot be relabelled a contradiction: both aggregate discovery and individual records reject that mismatch. A regression first failed against the initial semantic validator, then passed after the shared reason/state check. A future contradictory assessment requires a reviewed producer policy and compatible reason contract; this sprint never manufactures negative ethical findings from unknown data.

Pages use canonical-code/tag-ID keysets. Cursors bind the published snapshot and complete normalized query; a new publication returns a conflict requiring a fresh traversal. Each page uses a fresh read-only repeatable-read transaction, with the existing 10-second statement, 5-second lock and 2-MiB response bounds. Batch reads accept at most fifty unique codes, and pagination at most fifty funds. No POST, SQL caller input, raw evidence, writer connection, news ranking, freshness certification or positive green/sattvik badge is introduced.

An absent installation or unpublished snapshot is unavailable, not an empty classified universe. Existing empty/unavailable dataset behavior remains distinct. The new factory and every route need hosted PostgreSQL validation before release. CI requests prove database and application behavior; they do not impersonate a Google-authenticated caller or certify actual TI acceptance.

TI owns consumer implementation: render supported factual facets separately from the assessment/coverage states, expose dates and evidence identifiers, preserve exact scheme news, and label the generic thematic families as unassessed. A concrete contract handoff follows the reviewed source and CI evidence; no TI configuration or deployment is performed from MFData.
