## Preservation means data preservation, not frozen derived provenance

Every original source row and every old immutable observation, receipt, policy,
configuration and review event must retain its exact seal. No old source record
is replaced. The existing reversible projection remains the publication layer.

A same-AMC method revision necessarily adds new batch/decoder provenance. A fresh
ordinary Kotak September catalogue is also now available; a normal source check
can append another proof of the same financial fact. Comparing the bytes of a
derived provenance array would reject such additions even when no old evidence
or value changed. Do not silently remove that guard or exclude a sample.

Use a separately versioned, explicitly scoped preservation certificate:

1. The **whole** untouched ABSL/SBI/Kotak populations and protected pilot codes
   must have identical financial payloads across all four original read queries.
   Every old source assertion must remain byte-identical; additional provenance
   is permitted, but removal, replacement, altered values/dates/selection or a
   new conflict is not. Hash financial payloads in PostgreSQL without float
   round-tripping. This is not merely scalar sampling.
2. For the **whole** revised UTI population, retain every previously supported
   selected value/date **and every previously accepted source-period field**,
   and compare all previously supported month-end reported TER values
   independently. No accepted value may become a gap or change under this
   header-only method revision. Only properly source-qualified additions may
   fill previous gaps. Report exact before/after variant/field counts.
3. Continue the full whole-original and every-prior-layer immutable-row seals,
   fresh backup/restore, exact restricted-role/SQL-body checks and original-query
   equivalence proof. The evidence-format change is reviewed/tested code, not a
   runtime monkeypatch, arbitrary exclusion or preservation waiver.

Owner activation must verify target-value preservation within its existing
transaction and existing NAV-operation lock, using bounded sealed graph reads.
Do not hold the hot API view lock while hashing the entire raw database. Failed
verification must roll back publication; recovery must not depend on candidate
