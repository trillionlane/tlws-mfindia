# HDFC dynamic monthly publication

This focused successor builds on PR146's shared six-task gate. The old HDFC
publisher accepts only the retained September document and manually checked
values. A new issuer link alone cannot make it publish another period. The v2
method uses actual, corroborated printed dates and reviewed panel rules for the
same fixed HDFC Regular IDCW identity. It is implementation for independent
review; no deployment or live HDFC publication is asserted.

The immutable v1 registry, parser and numbered SQL remain unchanged. An explicit
owner transition selects multi-source policy 2, book composition 8 and current
policy 14 after shared profile 7. The four whole-book sources, their financial
specifications, retained hash membership, UTI v1, projection SQL and dormant
v5 default remain exact. The existing tables, append-only triggers, prior graph,
identity checks, private trigger-function boundary and existing roles are used.
No new consumer routes, grants, source activation or creator privileges appear.

## Discovery and field interpretation

The fixed official listing must link exactly one latest eligible issuer PDF.
The actual PDF dates on the AUM and BER panels must agree at month-end, both
fund-page footers must agree, and NAV context cannot be from another month or
future date. The fixed identity original and current database identity must
match. Identity-document date is never represented as monthly freshness.

The parser retains Regular BER, dated AUM rather than monthly average, the
labelled primary benchmark, and the complete scheme/gold/overseas manager panel.
Risk remains unavailable. Ambiguous individual fields remain unavailable and
cannot erase prior usable values; a wholly unusable panel is rejected. Real
September fields and existing manager-role context match the frozen v1 parser
exactly. Future-date variants in tests are explicitly synthetic, not evidence of
October issuer publication.

Worker source/policy/engine/version, page numbering/text hashes, full extraction
seal, document/selected-page counts and original SHA bindings are validated.
The snapshot retains all 24 selected page metadata and the two actual fund panel
numbers, plus the identity extraction and original listing reference/hash.

The old edition seal had exact source hashes and golden scalar values. The new
private trigger deliberately replaces that edition-specific authority with the
fixed cohort, pinned current parser engine and policy, retained issuer listing,
actual month-end, complete typed field/provenance checks and exact archives for
the snapshot's two PDFs. It does not independently parse PDFs in PostgreSQL.
The pinned worker remains responsible for confirming the issuer HTML link and
actual PDF contents; unknown layouts fail or withhold individual fields.

## Bounded execution and atomic publication

The HDFC request allocation is explicitly three: one listing up to 1 MiB,
one selected PDF up to 8 MiB and the retained identity PDF up to 8 MiB. The
aggregate is at most 17 MiB. This is the only request-bound change; the original
600-second task, shared 520-second wall, decoder 45-second wall/30-second CPU/
512 MiB limit, 120-second SQL/180-second transaction and 5-second lock limits
remain unchanged. No redirects, cookies, proxy, retry or denial bypass is added.

Financial work keys use the role-specific PDF hashes and actual reporting date,
current identity/population and derivation. The listing is retained discovery
evidence; changing a listing nonce alone does not create financial work. Known
identical inputs skip decoding/publication. Revised same-period bytes become
another candidate. Existing shared write-ahead claim/intent, actual publication
receipt and completion in one COMMIT, strongest effects and inspect-only recovery
remain in force. No old execution or uncertain claim is reset.

Owner installation changes configuration and the exact private trigger body,
not source/snapshot/run rows. It verifies the old and new source/API boundaries,
current graph and complete old business row inventory before commit. Re-entry
verifies installed state. Historical source constructors and allocations restore
whole predecessor bytes through one finite inverse stage; current allocation 4
binds actual new sources. Test-only history bookkeeping is separate from runtime
authority. Nothing is normalized by AST, ignored lines or wildcard hashes.
