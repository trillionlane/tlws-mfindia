## Observation and identity rules

A holding's checksum-valid ISIN remains an observed security even when no issuer mapping exists. Security-to-entity mappings and sector/domicile/theme attributes need explicit dated evidence. The initially packaged registry is empty: existing company names, broad article topics and scheme names do not establish those identities. No guessed links, country-from-ISIN inference, ESG/sattvik certification or missing-data-as-zero seed is shipped. Adding verified facts requires a reviewed registry change; this is not a claim that the current universe has usable issuer mappings.

The pure derivation verifies the existing snapshot/body/identity/policy hashes and retained engine identity, finite reported weights, complete-statement reconciliation, original denominator and exact row identity. It retains signed cash/net balances separately. Censored weights remain intervals; positive observed exposures are not normalized to 100 percent. Conflicting/date-ineligible security mappings withhold that entity; conflicting single-valued entity attributes are withheld across all held securities, not resolved by row order. Fund entities never imply underlying-company or country/theme look-through. Derivatives remain disclosed but are not netted into invented issuer exposures.

Every result binds the source snapshot/date, original content hashes, mapping registry, derivation source version and observation date. Evidence age is visible; no freshness cutoff or production SLA is invented. Absence/exclusion and freshness certification stay false. Revisions change the assessment identity. A retained engine hash is preserved, not replaced by today's runtime engine hash; historical accepted snapshots do not become invalid merely because code packaging changes. Original evidence, NAV/facts, fund IDs, aliases, generated family tags and generator/admin capabilities remain unchanged.

## Private API

Trusted composition is `mfdataindia.tagging.exposure_app:create_app`, extending TAG02/core/dataset routes. Default Docker composition is unchanged. Internal ingress, workload authentication, the direct non-elevated reader and TI partner authorization remain separate required infrastructure boundaries. No HTTP input selects a role, registry, SQL, profile or classifier.

- `GET /api/fund-exposures/v1` verifies the source boundary and reports retained snapshot/date bounds and explicit mapping-record coverage. Retained snapshots are not current-universe or freshness certification.
- `GET /api/fund-exposures/v1/funds/{code}` returns state, coverage/evidence metadata and security/entity/attribute counts.
- `GET /api/fund-exposures/v1/funds/{code}/{section}` reads `securities`, `entities` or `attributes`, at most fifty items.
- Subsequent pages send both the first page's `assessment_id` and `next_after`. Item IDs include their section; the server requires the actual after-item to exist in that section. Source/registry/observation changes return 409 rather than combining versions. Unknown/duplicate query members and invalid values produce bounded 422 responses.

Each read uses the existing repeatable-read/read-only transaction, 10-second statement, 5-second lock and 2-MiB response bounds. The domain guard retains three full installed-profile inspections per request: dataset, portfolio and its enrichment prerequisite. This work is constant per request, not per holding. Native checks measure one-item versus fifty-item pages; there is no cross-request security cache or raised timeout. Safe errors omit arbitrary exception values, SQL, raw source documents, URLs, credentials and provider responses.

An empty issuer registry produces explicit unmapped evidence, while actual dated securities remain readable. Missing enrollment/grants or unsafe privileges are unavailable, not a successful empty classification. `not_captured`, `identity_changed` and `conflicting` remain distinct. No tag HTTP writer, migrations, new roles, grants, source acquisition or schedule is introduced.
